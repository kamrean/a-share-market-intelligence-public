# P4 Publication and Ledger Methods

## Scope

P4 builds the local Stage7 publication chain and partial offline Stage8 quality
demonstration, not full P4/MVP or Stage8 acceptance. All external permissions
remain false; live benchmarks0/5, genuine model and real Telegram unverified.
P0-P3 artifacts and Blueprint v1 stay immutable.

The input boundary deliberately accepts only the fixed authored P3 synthetic
demo, recomputed with research.verify_demo and its pinned original assets.
This limited adapter is not a generic production API. A later reviewed live
integration must introduce genuine inputs, current freshness and authorization.
Changing a mode flag or bypassing recomputation is not integration.

## Report and Provenance

Keep the verified research input or equivalently lossless bounded provenance,
research/run and bundle identity, approved claims, reviews/evaluation and all
source/model/prompt/method/config fingerprints. Distinguish historical as_of
from actual generated/created time. Fact, inference, scenario, event outcome,
impact hypothesis and observed market reaction remain separate.

Exactly three logical parts:
1. Sourced news and upcoming events, retaining actual event states/times.
2. Five benchmark observations, breadth, turnover and unavailable flow.
3. Bounded sector statistics and exact approved claims with informational stance,
   counterarguments, invalidation and evidence references.

Render deterministic plain text, not untrusted HTML/Markdown execution.
No new model call or unsupported narrative. Derived items have stable IDs and
original references/methods. Each part/chunk carries report identity, part/chunk
identity, mode/as_of, correction identity and limitations. Do not zero-fill gaps.
Empty days are explicit where supported; fixed fixtures do not prove live event
discovery. Citation validity is not entailment or truth.

The publication guard checks recomputed report content/identity, allowed schema,
approved claims, sources, required domains, temporal semantics and forbidden
instructions. Synthetic eligibility uses historical as_of, never current-news
freshness. No external publication is authorized.

## Append-Only Ledger

Use one separate external SQLite ledger. Validate paths/links/hardlinks/sidecars
and existing application ID, exact schema/version/config read-only before mutation.
Reject P1/P3 or unrelated databases. Bound bytes, rows, text, reports and attempts.

Append a complete validated report before queue/delivery. Exact repeat identity
and content is idempotent; mismatched content fails closed. Transactions serialize
writers. Research rows and delivery history are append-only; status projections
may update separately. No API deletes/rewrites prior research. Hashes are not an
anti-tamper security boundary against arbitrary database rewriting.

Corrections are new records with supersedes and a bounded reason. Target must
exist and be current lineage leaf with matching synthetic dataset/mode/as_of.
Reject forks, dangling links, cycles and invalid ordinary-report links. The demo
clarifies limitations using the same verified claims, not invented observations.
Later factual corrections require new evidence/review.

## Simulated Delivery

Split the three logical parts into stable bounded Unicode plain-text chunks;
do not lose text or split a code point. Bind identity to exact report/part/ordinal/
content. Fixed synthetic sink only. Disabled Telegram mode makes zero requests
and reads no credentials. Trusted offline transport code is not live integration.

Persist queued status and reserve before each fake call. Only send the next
chunk after all predecessors are sent. One in-flight send per canonical store
across handles/restarts. Persist report/run, UTC-day and rate/volume bounds.
Clock rollback, changed configuration, unknown usage or exhaustion stops.
Separate stores are not global quotas and cannot bypass limits.

A fake acknowledgement must match reserved identity and sink before sent.
Definitive not-sent is failed; exception, timeout, malformed/absent receipt and
interrupted in-flight send are unknown. Both stop remaining sends and are never
automatically retried or reclassified across restart. Recovery is deferred.
Simulated sent is not real Telegram delivery; no exactly-once remote guarantee.

Synchronous fake adapters provide elapsed timeout detection, not hard cancellation.
Any live transport needs genuine deadlines under separately reviewed scope.

## Validation and Acceptance Gaps

Offline tests block sockets/DNS. Cover tampering, unsupported claims/instructions,
schema/temporal/cross-mode issues, correction integrity, duplicate/concurrent/
partial/unknown sends, persistent budget/rate/clock limits, storage/path/schema
guards and disabled live transport. Preserve all historical tests/protections.

Run python -m market_intelligence.publication demo with ephemeral external stores.
Save raw CLI JSON without numeric coercion and readable three-part report.
Verify recomputed content plus bounded actual execution metadata. Only documented
execution IDs/times may vary, never substantive evidence. Quality/error report
separates deterministic checks from unassessed semantics and missing live gates.
No fabricated human labels, matured outcomes or observation windows.

After human merge, prepare one grouped reviewed live-integration/MVP package:
permitted five-index and official news/event sources, genuine bounded model runs,
three dated end-to-end runs, human support sampling, user-designated private
Telegram test and correction. Missing access/rights/credentials/destination are
dependencies, not gaps fixtures can close. Long observation and VPS stay separate.
